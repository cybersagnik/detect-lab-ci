# T1016 — System Network Configuration Discovery

## Hypothesis
Adversaries enumerating local network configuration (`ipconfig`, `netstat`) to map the compromised host's network position, identify reachable subnets, and locate potential lateral movement targets. Network discovery is a near-universal early post-compromise action and is rarely performed by users interactively, making automated execution a high-fidelity indicator of malicious intent.

## Threat actor context
Used by: virtually every threat actor after initial access — APT28, APT29, Lazarus Group, FIN7, Emotet, TrickBot, and all commodity ransomware affiliates. Network configuration discovery is one of the first three ATT&CK techniques observed in the majority of incidents and is often chained with system information discovery (`systeminfo`) and account discovery (`net user`) within seconds of foothold.

## Telemetry required
- **Sysmon EventID 1** (ProcessCreate)
- `Image` ending with `\ipconfig.exe` or `\netstat.exe`
- `CommandLine` containing the full-discovery flags (`/all`, `-ano`, `-an`)
- `ParentCommandLine` — chained discovery commands indicate scripted recon

## Why standard detection misses this
Default endpoint monitoring allows `ipconfig` and `netstat` execution for legitimate troubleshooting. The technique only becomes visible when the same tools are run by a process that does not normally perform network troubleshooting (`powershell.exe`, `cmd.exe` from a non-admin shell, `mshta.exe`, custom RATs). The detection requires correlating the process creation with the parent process tree, which basic endpoint agents do not do.

## Detection logic
```yaml
detection:
  selection_ipconfig:
    Image|endswith: '\ipconfig.exe'
    CommandLine|contains: '/all'
  selection_netstat:
    Image|endswith: '\netstat.exe'
    CommandLine|contains:
      - '-ano'
      - '-an'
  condition: selection_ipconfig or selection_netstat
```

## Lab validation
- ART Test: `Invoke-AtomicTest T1016 -TestNumbers 1`
- Alert fired: Yes — Sysmon EID 1
- Image confirmed: `C:\Windows\System32\ipconfig.exe`
- Parent CommandLine observed: `cmd.exe /c ipconfig /all & netsh interface show interface & arp -a & nbtstat -n & net config`
- The full discovery chain visible in `ParentCommandLine` confirms automated reconnaissance

## Filter rationale
No filter applied — the detection signal is specific enough that additional filtering would only reduce coverage. `ipconfig /all` and `netstat -ano/-an` are not invoked by normal application startup paths, and the operator overhead of an occasional alert on a power-user running `ipconfig /all` from an admin shell is acceptable given the high adversary prevalence of this technique.

## Analyst triage guidance
On alert, check `Image`, `ParentImage`, and `ParentCommandLine` in Wazuh:
- If `ParentCommandLine` is a long chain of discovery commands joined with
  `&` or `;` (`ipconfig & net view & arp -a & nbtstat -n & net config`) —
  confirmed adversary reconnaissance, escalate
- A single `ipconfig /all` from `cmd.exe` opened by an interactive user
  in a helpdesk or sysadmin context is likely benign — close after review
- Cross-reference with the preceding few minutes for any `whoami`,
  `systeminfo`, `tasklist`, or `net user` alerts — a clustered run of
  discovery commands is the canonical post-foothold sequence
- `ParentImage` being `powershell.exe`, `mshta.exe`, `rundll32.exe`, or
  any LOLBin is high-confidence malicious regardless of context
