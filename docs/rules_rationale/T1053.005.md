# T1053.005 — Suspicious Scheduled Task Creation via schtasks.exe
 
## Hypothesis
Adversaries creating scheduled tasks via `schtasks.exe` that run
executables from user-writable locations or spawn interpreter processes
as a persistence mechanism surviving reboots and user logoffs.
 
## Threat actor context
Used by: Emotet, Qbot, FIN7, Lazarus Group, and most enterprise-targeting
ransomware families. One of the most reliable Windows persistence mechanisms
— tasks survive reboots, can run as SYSTEM, and are commonly overlooked
during initial IR triage due to volume of legitimate task creation activity.
 
## Telemetry required
- **Sysmon EventID 1** (ProcessCreate)
- Image: `schtasks.exe`
- CommandLine: `/Create` + `/TR` (task run — specifies what executes)
- **Windows Security EventID 4698** (secondary — scheduled task created)
## Why standard detection misses this
Monitoring all `schtasks /Create` events generates extreme noise — Windows
creates tasks constantly for updates, maintenance, and telemetry. Filtering
by ParentImage is dangerous (parent processes are common injection targets).
The signal must come from WHAT the task runs, not just that a task was created.
 
## Detection logic
```yaml
detection:
  selection_base:
    Image|endswith: '\schtasks.exe'
    CommandLine|contains|all:
      - '/Create'
      - '/TR'
  selection_suspicious:
    CommandLine|contains:
      - 'powershell'
      - 'cmd.exe'
      - 'wscript'
      - 'cscript'
      - 'mshta'
      - 'regsvr32'
      - '\Temp\'
      - '\AppData\Local\Temp'
      - '\AppData\Roaming'
  filter_safe:
    CommandLine|contains:
      - '/TR "C:\Windows\'
      - '/TR "C:\Program Files\'
      - '/TR "C:\Program Files (x86)\'
  condition: selection_base and (selection_suspicious or not filter_safe)
```
 
## Lab validation
- ART Test: `Invoke-AtomicTest T1053.005 -TestNumbers 1`
- Alert fired: Yes — Sysmon EID 1 and Windows Security EID 4698
- CommandLine confirmed: `schtasks /Create /SC ONCE /TR cmd.exe`

## Filter rationale
The `filter_safe` block excludes tasks whose `/TR` argument points at a
protected install path (`C:\Windows\`, `C:\Program Files\`,
`C:\Program Files (x86)\`). These paths are not writable by non-elevated
user processes and are the canonical locations for first-party scheduled
tasks created by Windows Update, Office, and most enterprise deployment
tools. The trade-off is that a low-fidelity subset of legitimate admin
activity (admin scripts scheduled by hand) is intentionally retained for
review rather than suppressed — the signal in the suspicious paths and
interpreter strings is strong enough that the cost of suppression outweighs
the analyst review time.

The `selection_suspicious` block deliberately retains `powershell` as a
flag even though it overlaps with benign PowerShell-driven task creation.
Filtering `powershell` as a parent entirely would blind the rule to its
primary detection target (malware creating tasks that run PowerShell).

## Analyst triage guidance
On alert, check `Image`, `CommandLine`, and the resulting Windows Security
EID 4698 task name in Wazuh:
- Confirm `Image` is `schtasks.exe` and `/TR` target is a suspicious path
  or interpreter (`powershell`, `cmd.exe`, `mshta`, `regsvr32`, `wscript`,
  `cscript`) — escalate
- If `/TR` resolves to a path under `C:\Windows\` or `C:\Program Files\`
  — likely a first-party update or installer, close as benign
- Cross-reference EID 4698 for the registered task name — attacker task
  names are often random strings or attempt to mimic legitimate names
- If `ParentImage` is a known admin tool and the task runs from a protected
  path — review but unlikely malicious
