# T1057 — Process Discovery via tasklist.exe

## Hypothesis
Adversaries enumerating running processes with `tasklist.exe` to identify security tools (AV/EDR), locate high-value processes to migrate into, or build a target list for follow-on actions such as token theft or process killing. Process discovery is one of the earliest post-foothold actions and frequently chains with system information discovery within seconds.

## Threat actor context
Used by: Lazarus Group, APT32, FIN7, Cobalt Strike default beacon, TrickBot, and most commodity loaders. The technique is observed in the majority of post-exploitation frameworks as a reconnaissance primitive and is often the first indicator that a foothold has been obtained by an actor with hands-on-keyboard intent.

## Telemetry required
- **Sysmon EventID 1** (ProcessCreate)
- `Image` ending with `\tasklist.exe`
- `ParentImage` — context for whether the invocation is interactive or
  scripted

## Why standard detection misses this
`tasklist.exe` is a first-party Microsoft binary that interactive users
launch regularly (Task Manager shortcut, manual troubleshooting). Endpoint
agents rarely alert on its execution because of this benign volume.
The signal only emerges when `tasklist.exe` is invoked by a non-interactive
parent process — `powershell.exe`, `cmd.exe` from a non-shell parent,
`mshta.exe`, or any LOLBin — which basic loggers do not evaluate.

## Detection logic
```yaml
detection:
  selection:
    Image|endswith: '\tasklist.exe'
  filter_ui:
    ParentImage|endswith: '\explorer.exe'
  condition: selection and not filter_ui
```

## Lab validation
- ART Test: `Invoke-AtomicTest T1057 -TestNumbers 2`
- Alert fired: Yes — Sysmon EID 1
- Image confirmed: `C:\Windows\System32\tasklist.exe`
- The full process list was captured in the VM output, including svchost,
  OneDrive, and explorer — standard post-compromise recon output

## Filter rationale
The `filter_ui` block excludes `tasklist.exe` invocations where
`ParentImage` ends with `\explorer.exe`. This corresponds to a user
double-clicking the Task Manager shortcut or right-clicking the taskbar,
both of which spawn `tasklist.exe` (or its UI equivalent) from the
interactive shell. The remaining detections are programmatic invocations
from scripting interpreters or LOLBins — these are the post-compromise
reconnaissance pattern.

## Analyst triage guidance
On alert, check `ParentImage` and `ParentCommandLine` in Wazuh:
- If `ParentImage` is `powershell.exe`, `cmd.exe`, `mshta.exe`,
  `rundll32.exe`, `wscript.exe`, or `cscript.exe` — confirmed adversary
  reconnaissance, escalate
- If `ParentImage` is `explorer.exe` and the process is interactive user
  activity — close as benign
- Cross-reference with the preceding minute for any `whoami`, `net user`,
  `ipconfig`, or `systeminfo` alerts — a clustered discovery sequence is
  the canonical post-foothold chain
- `tasklist` followed within seconds by `taskkill` against an AV/EDR
  process (`MsMpEng.exe`, `csfalconservice.exe`, `cb.exe`) is a
  high-confidence defence-evasion sequence
