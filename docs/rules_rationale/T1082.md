# T1082 — System Information Discovery via systeminfo.exe

## Hypothesis
Adversaries executing `systeminfo.exe` to harvest host details — OS version, install date, hotfix list, domain/workgroup membership, network adapter configuration, memory, and manufacturer — to fingerprint the host, identify missing patches for exploit selection, and determine whether the machine is a domain controller, a developer workstation, or a server. The output is the foundation for tailoring subsequent post-exploitation actions.

## Threat actor context
Used by: Lazarus Group, APT28, APT29, FIN7, Cobalt Strike default recon module, and virtually every post-exploitation framework. System information discovery is observed in the first minute of every hands-on-keyboard intrusion and is often chained with network discovery and account discovery to build the complete target picture.

## Telemetry required
- **Sysmon EventID 1** (ProcessCreate)
- `Image` ending with `\systeminfo.exe`
- `ParentCommandLine` — the surrounding command context determines
  whether this is automated recon or interactive troubleshooting
- Output is not in telemetry directly — Sysmon records the process
  creation event, not the captured stdout of the command

## Why standard detection misses this
`systeminfo.exe` is a first-party binary commonly used by interactive
administrators and by Windows itself during troubleshooting. Endpoint
agents rarely alert on its invocation. The signal only emerges when
`systeminfo.exe` is invoked by a process that does not normally run
system inventory (`powershell.exe`, `cmd.exe` from a non-admin shell,
LOLBins) or when it is part of a chained discovery sequence visible
in `ParentCommandLine`.

## Detection logic
```yaml
detection:
  selection:
    Image|endswith: '\systeminfo.exe'
  filter_legitimate:
    ParentImage|endswith:
      - '\msiexec.exe'
      - '\setup.exe'
  condition: selection and not filter_legitimate
```

## Lab validation
- ART Test: `Invoke-AtomicTest T1082 -TestNumbers 1`
- ART Test Name: System Information Discovery
- Alert fired: Yes — Sysmon EID 1
- Image confirmed: `C:\Windows\System32\systeminfo.exe`
- Parent Image confirmed: `C:\Windows\System32\cmd.exe`
- Parent CommandLine observed:
  `cmd.exe /c systeminfo & reg query HKLM\SYSTEM\CurrentControlSet\Services\Disk\Enum`
- Full system information captured in VM output: OS version, domain
  (`WORKGROUP`), hotfixes, NIC details — standard adversary reconnaissance

## Filter rationale
The `filter_legitimate` block excludes `systeminfo.exe` invocations where
`ParentImage` ends with `\msiexec.exe` or `\setup.exe`. Both installer
processes call `systeminfo.exe` during prerequisite checks to determine
OS version and architecture before proceeding with installation. This
filtering removes the predictable noise generated by software deployment
without suppressing the more interesting invocations from `cmd.exe`,
`powershell.exe`, or LOLBins.

## Analyst triage guidance
On alert, check `ParentImage` and `ParentCommandLine` in Wazuh:
- If `ParentCommandLine` is a chained discovery command
  (`systeminfo & net view & ipconfig & tasklist`) — confirmed adversary
  reconnaissance, escalate
- A standalone `systeminfo` from `cmd.exe` opened interactively by an
  admin user is likely benign — close after review
- `ParentImage` being `powershell.exe`, `mshta.exe`, `rundll32.exe`,
  or any LOLBin is high-confidence malicious regardless of the
  surrounding command context
- Cross-reference with preceding minutes for `whoami`, `net user`,
  `nltest`, or `tasklist` — a clustered run of discovery commands is
  the canonical post-foothold sequence
