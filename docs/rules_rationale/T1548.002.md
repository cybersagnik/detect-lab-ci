# T1548.002 — UAC Bypass via Fodhelper.exe

## Hypothesis
Adversaries manipulating the `HKCU\Software\Classes\ms-settings\Shell\Open\command` registry key then executing `fodhelper.exe` to spawn a child process with an elevated integrity token without triggering a UAC consent prompt. `fodhelper.exe` is an auto-elevating Microsoft binary with no legitimate reason to spawn child processes, making any child process observation a high-confidence indicator of bypass.

## Threat actor context
Used by: UACME project (open-source catalogue of bypass methods), multiple commodity loaders, and several APT families. Fodhelper is one of the most popular UAC bypass vectors because the underlying binary is signed by Microsoft and trusted by application whitelisting. The technique bypasses UAC silently and is frequently used in the first minutes after initial access to obtain elevated privileges for follow-on actions.

## Telemetry required
- **Sysmon EventID 1** (ProcessCreate)
- `ParentImage` ending with `\fodhelper.exe`
- Child `Image` and `CommandLine` — what was spawned elevated

## Why standard detection misses this
Default process execution monitoring treats `fodhelper.exe` as a legitimate Microsoft binary and rarely alerts on its child processes. The UAC bypass is silent — no prompt appears — so user-visible indicators are absent. Endpoint protection that only flags unsigned or unknown binaries misses a signed Microsoft executable doing the launching.

## Detection logic
```yaml
detection:
  selection:
    ParentImage|endswith: '\fodhelper.exe'
  condition: selection
```

## Lab validation
- ART Test: `Invoke-AtomicTest T1548.002 -TestNumbers 3`
- Alert fired: Yes — Sysmon EID 1
- ParentImage confirmed: `C:\Windows\System32\fodhelper.exe`
- Child Process observed: `cmd.exe` spawned with High integrity token — no UAC prompt
- Cleanup Command: `Invoke-AtomicTest T1548.002 -TestNumbers 3 -Cleanup`

## Filter rationale
No filter applied — `fodhelper.exe` has no documented legitimate child-process behaviour in interactive sessions. Auto-elevation is only used to register a "Manage Optional Features" UI handler, which does not invoke external processes. Any observable child process from `fodhelper.exe` is treated as a bypass attempt.

## Analyst triage guidance
On alert, check `Image` and `CommandLine` of the child process in Wazuh:
- If the child is `cmd.exe`, `powershell.exe`, `rundll32.exe`, or any scripting interpreter — confirmed bypass, escalate immediately
- If the child is `ms-settings.exe` from a real user-initiated "Manage Optional Features" launch — review the parent registry key write under `ms-settings\Shell\Open\command`; if absent, it is bypass
- Cross-reference with the Sysmon EID 13 registry event for the `ms-settings\Shell\Open\command` key write — it normally occurs seconds before the `fodhelper.exe` spawn
